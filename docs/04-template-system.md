# Level 4｜模板與知識層：模板庫與 Output SLA

> 讓 Prompt 從個人技巧變成可重複、可分享、可驗收的團隊資產。

Level 1–3 解決「單次 prompt 寫得好」；Level 4 解決「每次都寫得好，而且別人也能用」。

---

## 1. 場景模板庫

| 類型 | 模板 | 適用 |
| --- | --- | --- |
| 通用 | [萬用模板](templates/general.md) | 任何任務；含完整版、極簡版、JSON 版 |
| 技術設計 | [程式與專案模板](templates/programming.md) | 專案掃描、架構設計、重構、技術選型 |
| 商業決策 | [投資分析模板](templates/investment.md) | 個股或產業分析（寫法示範） |
| 結構化 | [prompt-template.json](templates/prompt-template.json) | 存檔、表單化、串接自動化工具 |

**建議再自行擴充的模板類型**

- 教學講解：初學者友善講解、分步驟推導
- 批判辯證：反方挑戰、假設驗證
- 商業：競爭分析、風險矩陣

新增模板時，沿用 [萬用模板](templates/general.md) 的段落順序與 JSON 欄位，團隊成員才不必重新學。

---

## 2. Output SLA（輸出品質標準）

事先定義「什麼叫做好」，才能驗收輸出、比較 prompt 版本。

| 面向 | 定義 | 檢查問題 |
| --- | --- | --- |
| **清晰度** | 讀者能快速理解 | 一句話版本能說清楚結論嗎？ |
| **邏輯一致性** | 結論由前提推得、前後不矛盾 | 有沒有推理跳躍？ |
| **可執行性** | 讀完知道下一步做什麼 | 有具體步驟與優先順序嗎？ |
| **風險揭露** | 說明主要風險與不確定性 | 有提到最壞情境嗎？ |
| **假設透明度** | 明列所依賴的假設與資料時間點 | 假設錯了結論會怎樣？ |

這五個面向可直接轉為 1–5 分評分表，用法見 [評估與迭代](07-evaluation-iteration.md)。

---

## 3. 團隊標準化建議

1. **版本控管**：模板以檔案存在 repo（如本專案），修改走 PR，並在 [CHANGELOG](../CHANGELOG.md) 記錄。
2. **一個欄位一個意思**：Markdown 段落與 JSON 欄位一一對應，避免同一概念有多種名稱。
3. **附上範例**：每個模板至少一個填好的實例，比說明文字更好懂。
4. **附上驗收方式**：模板說明它適用的 SLA 面向與測試案例。
5. **放進工具的脈絡**：常用規則寫進 AI 工具的專案說明檔（如 `CLAUDE.md`），每次對話自動套用。見 [Agent 與 Context Engineering](06-agent-context-engineering.md)。

---

## 4. 依任務價值選層

| 任務價值 | 使用層級 | 例子 |
| --- | --- | --- |
| 低 | Level 1 | 寫一段自我介紹、翻譯一封信 |
| 中 | Level 1 + 2 | 架構設計、深度研究 |
| 高 | Level 1 + 2 + 3 | 技術選型、投資判斷 |
| 團隊標準化 | 全部 + 評估 | 共用模板、自動化流程 |

不要為了完整而完整：模組越多，prompt 越長、越難維護，也可能讓模型分散注意力。
