# 現代最佳實踐：推理模型、結構化與長文件

> 模型能力演進後，有些舊技巧不再必要，有些則更重要。本篇整理跨模型通用的做法，可搭配任何一層使用。

---

## 1. 寫給推理模型

多數主流模型會在回答前自行思考。寫法跟著調整：

| 舊做法 | 現在建議 |
| --- | --- |
| 「請逐步思考」 | 說清楚目標、判準與理由；需要更深時調高思考強度，或寫「請仔細考慮邊界情況」 |
| 列出每一個思考步驟 | 給目標與驗收條件，讓模型決定步驟 |
| 「嚴禁」「絕對不可」、全大寫 | 一般語氣 + 理由；過度強調會讓模型在無關處也過度套用 |
| 只寫「不要 X」 | 寫「請做 Y」；必要時再補「避免 X，因為…」 |
| 一次塞入所有要求 | 拆成多步（見 Prompt Chaining） |

**說明理由比加強語氣有效。** 例如：

- 較差：「絕對不要用省略號。」
- 較好：「回答會由語音合成朗讀，請不要使用省略號，因為語音引擎無法唸出它。」

模型理解原因後，能自行推廣到沒列出的情況。

## 2. 用標籤組織 prompt

用 XML 風格的標籤區隔指令、資料與範例，模型較不會混淆「要處理的內容」和「給它的指示」。

```text
<instructions>
請根據合約內容，列出所有付款條件與期限。
</instructions>

<contract>
（合約全文）
</contract>

<output_format>
表格：條款編號｜付款條件｜期限
</output_format>
```

- 標籤名稱自訂即可，保持一致並在指令中引用（「根據 `<contract>` 中的內容…」）。
- 多份文件時，每份用 `<document>` 包住，並附上 `<source>`、`<date>` 等中繼資料。
- 舊版的 `<<< >>>` 仍可用，但無法命名或區分多份資料。

## 3. 長文件技巧

| 技巧 | 做法 | 為什麼 |
| --- | --- | --- |
| **資料在前，問題在後** | 長文件放 prompt 開頭，Task 放最後 | 多數模型在這種順序下回答品質較好 |
| **先引用再回答** | 「先在 `<quotes>` 中摘錄相關原文，再根據引文回答」 | 讓模型聚焦在真正相關的段落，也方便你核對 |
| **分段處理** | 超長資料先分段摘要，再彙整 | 降低遺漏中段內容的機率 |
| **標示來源** | 每份文件附來源與日期 | 方便模型引用、方便你追溯 |

---

## 4. 降低幻覺

1. **允許說不知道**：「若資料中沒有答案，請直接說明，不要推測。」
2. **限定資料範圍**：「只根據 `<document>` 中的內容回答。」
3. **要求引用**：每個關鍵主張附上原文或來源。
4. **標示時間點**：模型知識有截止日期；涉及價格、法規、版本號時，要求標示資料日期，或由你提供最新資料。
5. **事後驗證**：重要數字另外查證；或另開對話，請模型逐條檢查前一次輸出的主張是否有依據。

---

## 5. Prompt Chaining：拆成多步

一個 prompt 做太多事，每件事都做不好。把大任務拆成串接的步驟，前一步的輸出作為下一步的輸入：

```text
步驟 1：摘要 → 從 10 份會議紀錄抽出決議與待辦（輸出到 <summary>）
步驟 2：分析 → 根據 <summary> 找出衝突的決議與遺漏的負責人
步驟 3：產出 → 根據分析結果撰寫給主管的一頁報告
步驟 4：審查 → 請模型以審查者身份檢查報告是否有錯誤或遺漏
```

好處：每一步都能單獨檢查與調整，出錯時知道是哪一步。

---

## 6. Meta-prompting：讓模型幫你改 prompt

```text
以下是我目前的 prompt 與一次不滿意的輸出。
請指出 prompt 中哪些地方不清楚、缺少哪些 Context，並提出改寫版本。

<prompt>…</prompt>
<output>…</output>
<what_i_wanted>…</what_i_wanted>
```

多數 AI 平台也提供 prompt 產生器或改善工具，可先產生初稿再依本指南調整。

---

## 7. 結構化輸出

- **聊天介面**：在 Format 中給出 JSON 範例即可。
- **API 或自動化流程**：使用平台的結構化輸出功能（以 JSON Schema 定義欄位），由系統保證格式正確，比只在 prompt 中要求可靠。
- 要求 JSON 時，同時說明每個欄位的意義與允許值，空值如何表示。

---

## 8. 其他實用技巧

| 技巧 | 說明 |
| --- | --- |
| 系統提示放長期規則 | 角色、語氣、固定限制放系統提示或專案說明檔；單次任務放使用者訊息 |
| 給讀者而非頭銜 | 「讀者是非技術主管」通常比「你是溝通專家」更能調整輸出 |
| 示範長度與語氣 | 想要簡短口語，prompt 本身也寫得簡短口語 |
| 多模態 | 圖片、截圖、PDF 可直接附上；說明要它看哪個部分 |
