# Agent 與 Context Engineering

> AI 代理（如 Claude Code、Cursor、Codex 等）會自己讀檔、執行指令、修改程式。對它們而言，重點從「寫一句好 prompt」轉為**設計模型看得到的整體脈絡**。

---

## 1. 從 Prompt Engineering 到 Context Engineering

代理每一步看到的內容，來自好幾個來源：

| 來源 | 內容 | 誰負責 |
| --- | --- | --- |
| 系統提示 | 工具的基本行為規則 | 工具廠商 |
| 專案說明檔 | 專案規則、常用指令、架構（`CLAUDE.md`、`AGENTS.md`、`.cursor/rules`） | 你 |
| 任務訊息 | 這次要做什麼 | 你 |
| 工具結果 | 讀到的檔案、指令輸出、搜尋結果 | 代理自己取得 |
| 對話歷史 | 先前的討論與決定 | 累積而來 |

PTCF 仍然適用，只是分布到不同位置：

| PTCF | 在代理情境中的位置 |
| --- | --- |
| Persona | 通常不必寫；專案說明檔描述「這個專案的慣例」更有用 |
| Task | 任務訊息：目標、範圍、驗收條件 |
| Context | 專案說明檔 + 代理自己讀程式碼；你補充它讀不到的（商業背景、為什麼要改） |
| Format | 交付物：程式修改、測試、PR 說明、報告 |

## 2. 給代理的任務怎麼寫

好的任務包含四件事：

| 項目 | 範例 |
| --- | --- |
| **目標** | 匯出報表時支援 CSV 格式 |
| **範圍** | 只改 `export/` 模組；不要動資料庫結構 |
| **驗收條件** | 現有測試全部通過；新增 CSV 匯出的測試；手動匯出一份確認欄位正確 |
| **限制** | 不新增第三方套件（需經資安審核） |

```text
目標：匯出報表時支援 CSV 格式。
範圍：只改 export/ 模組，不要動資料庫結構。
驗收：現有測試全過，並新增 CSV 匯出的測試。
限制：不新增第三方套件，因為新套件需經資安審核。
完成後請列出你沒有驗證到的部分。
```

**常用句型**

| 情境 | 說法 |
| --- | --- |
| 大改動 | 「先提出計畫，列出會改的檔案與風險，等我核准再動手。」 |
| 修 bug | 「先重現問題 → 寫一個會失敗的測試 → 修正 → 確認全部測試通過。」 |
| 不確定 | 「先別動手，告訴我你打算改哪些檔案、為什麼。」 |
| 接手陌生程式 | 「讀 README 與主要進入點，用 5 句話說明資料流，並指出最容易壞的 3 個地方。」 |
| 收尾 | 「列出所有修改，逐檔說明理由，以及沒有驗證到的地方。」 |

## 3. 專案說明檔（CLAUDE.md／AGENTS.md）

每次對話都會自動載入，適合放**長期有效、無法從程式碼直接看出**的資訊。

**該寫**

- 建置、測試、執行的指令（尤其是怎麼跑單一測試）
- 需要讀好幾個檔案才能理解的架構
- 專案特有的慣例與禁忌，以及**原因**
- 容易踩的坑

**不必寫**

- 程式碼本身就看得出來的事（檔案清單、函式說明）
- 通用的開發原則（「寫測試」「不要洩漏密碼」）
- 只跟這次任務有關的內容

**範例**

```markdown
# CLAUDE.md

## 指令
- 測試：`npm test`；單一測試：`npm test -- -t "測試名稱"`
- 型別檢查：`npm run typecheck`（commit 前必跑）

## 架構
- API 請求一律經過 `src/api/client.ts`，它負責重試與錯誤轉換；不要在元件中直接呼叫 fetch。
- 狀態管理只用 Zustand；`src/legacy/` 下的 Redux 程式碼正在淘汰，不要新增。

## 慣例
- 金額一律用整數（分）儲存，避免浮點誤差。
- 使用者介面文字用繁體中文，放在 `src/i18n/zh-TW.json`。
```

**原則**：保持精簡。說明檔每次都佔用脈絡空間，太長反而稀釋重點。必須「每次都發生」的檢查（如格式化、lint），應交給工具的 hook 或 CI，而不是只寫在說明檔裡。

## 4. 工具與檢索資料的脈絡

如果你在開發自己的代理或 AI 應用：

- **工具描述就是 prompt**：說明工具做什麼、什麼時候該用、什麼時候不該用、參數的格式與範例。
- **工具結果要精簡**：回傳必要欄位即可，避免把大量無關資料塞進脈絡。
- **檢索資料附中繼資料**：來源、日期、可信度，讓模型能引用與取捨。
- **長任務要管理脈絡**：定期摘要進度、把中間結果寫入檔案，而不是讓對話無限增長。

---

## 5. 護欄

- **先 commit 再讓代理改**，改完看 diff；出錯時可以立即還原。
- **危險動作維持人工核准**：刪除檔案、push、merge、發版、對外發送訊息。
- **要求如實回報**：哪些有測試、哪些沒驗證、做了哪些假設。「應該可以」不等於「驗證過」。
- **不要把密碼、金鑰、客戶資料**貼進對話或寫進說明檔。
